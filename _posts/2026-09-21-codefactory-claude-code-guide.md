## 1. 단순 질의응답을 넘어선 "터미널 속 페어 프로그래머"

대다수의 개발자가 웹 브라우저 채팅창에서 코드를 복사-붙여넣기 하는 방식으로 AI를 사용합니다. 하지만 코드팩토리가 제시하는 Claude Code의 핵심 가치는 **"개발자의 터미널과 개발 환경에 완전히 녹아든 자율 에이전트"**입니다.

Claude Code는 코드베이스 전체를 직접 탐색하고, 터미널 명령을 스스로 실행하며, git 상태를 능동적으로 파악합니다. 이를 현업 실무에 성공적으로 안착시키기 위한 4단계 핵심 워크플로우를 정리합니다.

---

## 2. 현업 개발자를 위한 4단계 실전 파이프라인

```text
[1. 컨텍스트 고정] ──▶ [2. 작은 단위 작업 위임] ──▶ [3. 자동 검증 루프] ──▶ [4. Git 원자적 커밋]
  (CLAUDE.md 주입)     (1회에 1개 함수/파일)       (테스트 & 린트 실행)    (Conventional Commit)
```

### Step 1. 프로젝트 메모리(CLAUDE.md) 선제 주입
Claude Code는 매 세션 시작 시 프로젝트 루트의 `CLAUDE.md`를 자동으로 읽습니다. 여기에 팀의 코딩 컨벤션, 빌드 명령어, 금지해야 할 패턴을 명시해 두면 불필요한 잔소리 프롬프트를 90% 줄일 수 있습니다.

```markdown
# 우리 팀의 Claude Code 핵심 가이드
- 패키지 매니저는 반드시 `pnpm`을 사용한다.
- 비즈니스 로직은 `services/` 폴더에 두고, 컨트롤러에 직접 DB 쿼리를 작성하지 않는다.
- 작업 완료 전 반드시 `pnpm test`와 `pnpm lint`를 실행해 성공 여부를 확인한다.
```

### Step 2. '거대한 요청' 대신 '원자적 태스크' 단위 위임
- **안티패턴:** *"우리 앱에 결제 시스템이랑 알림 기능 다 만들어줘."* ➡️ 컨텍스트 한도 초과 및 버그 발생.
- **모범 사례:** *"결제 모듈의 웹훅 핸들러에서 서명(Signature) 검증 로직만 구현하고 테스트 코드를 붙여줘."* ➡️ 1회에 1개 모듈씩 명확한 바운더리로 지시.

### Step 3. 하네스 기반 자동 검증 (Verify Loop)
코드팩토리가 강조하는 바이브 코딩의 핵심은 "AI가 짠 코드를 맹신하지 않고, **테스트 스위트가 검증하게 만드는 것**"입니다.
- AI에게 코드를 수정하게 한 뒤 *"방금 수정한 모듈의 단위 테스트를 실행하고, 통과하지 못하면 스스로 고쳐"*라고 지시합니다.
- 사람이 눈으로 코드를 일일이 디버깅하지 않고, 실패한 테스트 로그를 AI가 다시 읽고 자가 치유(Self-healing)하도록 만듭니다.

### Step 4. 원자적 Git 커밋과 PR 분리
작업이 끝날 때마다 Claude Code에게 바로 커밋을 맡길 수 있습니다:
```bash
# 터미널 내 Claude Code 지시 예시
> 방금 결제 서명 검증 로직 추가한 거 Conventional Commits 형식으로 커밋 메시지 작성해서 커밋해줘.
```

## 3. 실무 효율을 2배 높이는 슬래시 커맨드 활용법

| 명령어 | 실무 활용 팁 |
| :--- | :--- |
| `/compact` | 대화가 길어져 지연 시간이 늘어날 때, 핵심 컨텍스트만 남기고 이전 대화 로그를 압축 |
| `/review` | PR을 올리기 전 현재 git diff를 전체적으로 훑어보며 누락된 에러 핸들링이나 보안 취약점 사전 탐지 |
| `/clear` | 하나의 기능 구현이 끝나면 세션을 완전히 비워 다음 작업에 이전 잔재가 남지 않도록 초기화 |

---

## 4. 요약: 바이브 코딩의 본질은 "아키텍처 설계와 감독"

코드팩토리가 정의하는 현대 개발자의 역할은 **"타이핑하는 사람"에서 "설계하고 감독하는 사람(Tech Lead)"**으로 변화하고 있습니다:

> "세부 구현은 Claude Code에게 전담시키고, 개발자는 전체 디렉토리 구조, 데이터 모델의 일관성, 그리고 테스트 하네스의 견고함을 챙기는 데 집중해야 합니다."
