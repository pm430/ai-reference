## 3대 핵심 개념 한눈에 비교하기

Claude Code를 효율적으로 다루기 위해서는 사용자가 직접 내리는 **커맨드(Command)**, AI의 역량을 확장하는 **스킬(Skill)**, 그리고 복잡한 작업을 격리해 수행하는 **서브에이전트(Sub-agent)**의 역할을 명확히 구분해야 합니다.

| 개념 | 주체 | 컨텍스트 공유 여부 | 주요 역할 | 대표 예시 |
| :--- | :---: | :---: | :--- | :--- |
| **커맨드 (Command)** | 사용자 | 메인 세션 제어 | 세션 초기화, 모델 전환, 설정 조회 | `/clear`, `/model`, `/compact` |
| **스킬 (Skill)** | AI (사용자 트리거 가능) | 메인 컨텍스트 내 로드 | 특정 작업의 절차적 지침·스크립트 제공 | `webapp-testing`, `api-doc-gen` |
| **서브에이전트 (Sub-agent)** | AI (메인 에이전트가 호출) | **완전 격리 (독립 세션)** | 대규모 리서치, 코드베이스 전수 탐색, 병렬 작업 | 배경 탐색 subagent, 테스트 실행기 |

---

## 1. 커맨드 (Command) — 세션을 제어하는 운전대

커맨드는 사용자가 슬래시(`/`)로 시작하여 입력하는 **메타 제어 명령**입니다. AI와 잡담을 나누는 대신 에이전트 도구 자체의 동작을 즉시 제어합니다.

- `/clear`: 이전 대화 기록을 비우고 깨끗한 컨텍스트에서 새 작업을 시작합니다.
- `/compact`: 대화가 길어져 토큰 한도에 다다랐을 때, 핵심 요약만 남기고 불필요한 도구 호출 로그를 압축합니다.
- `/review`: 현재 작업 공간의 변경 사항(git diff)을 일괄 검토하도록 요청합니다.

## 2. 스킬 (Skill) — 에이전트의 지식 및 도구 확장팩

스킬은 에이전트에게 "이런 작업은 이렇게 처리해"라는 전문 노하우(`SKILL.md`)를 주입하는 플레이북입니다.

- **장점**: 프롬프트를 매번 길게 치지 않아도, "E2E 테스트 돌려줘" 한마디에 스킬 내부의 복잡한 절차(포트 확인 ➡️ Playwright 구동 ➡️ 스크린샷 캡처 ➡️ 리포트 생성)가 자동으로 실행됩니다.
- **적용 단위**: 프로젝트 루트(`.agents/skills/`)에 두어 팀 전체가 공유하거나, 홈 디렉토리(`~/.claude/skills/`)에 두어 개인 전역에서 사용할 수 있습니다.

## 3. 서브에이전트 (Sub-agent) — 메인 대화를 보호하는 분신

서브에이전트는 메인 에이전트가 "하위 작업"을 맡기기 위해 자식 프로세스처럼 띄우는 **독립된 에이전트**입니다.

- **컨텍스트 오염 방지**: 코드베이스 전체에서 특정 키워드를 찾기 위해 100개의 파일을 뒤져야 할 때, 이를 메인 대화에서 다 읽으면 대화창의 토큰 윈도우가 가득 차버립니다. 서브에이전트가 별도 메모리에서 100개 파일을 읽고 최종 3줄 요약만 메인 에이전트에게 전달합니다.
- **병렬 처리**: 브라우저 화면 검증, 터미널 장기 실행 프로세스 감시 등 독립적인 실행 환경을 제공합니다.

## 실무 결정 가이드: 언제 무엇을 써야 할까?

```text
[목표: 해결하려는 상황]
  │
  ├─ 대화 컨텍스트가 너무 차서 세션을 리셋/압축하고 싶다 ──▶ [Command] (/compact, /clear)
  │
  ├─ 우리 팀만의 코딩 컨벤션이나 배포 절차를 기억시키고 싶다 ──▶ [Skill] (SKILL.md)
  │
  └─ 수백 개 파일을 조사하거나 장기 백그라운드 작업을 돌려야 한다 ──▶ [Sub-agent] (독립 컨텍스트 위임)
```

> **핵심 요약:**  
> 명령어로 세션을 깔끔하게 관리하고, 스킬로 전문 지식을 장착하며, 서브에이전트로 무거운 조사를 위임하는 것이 숙련된 AI 페어 프로그래밍의 3박자입니다.
